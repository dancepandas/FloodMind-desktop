# AI 平台执行过程输出样式调研（2026-08-12）

> 针对「执行中状态行 + 流式回答 + 完成后过程展示」的交互样式，调研主流 AI 平台
> （ChatGPT、Claude、Kimi、Perplexity、Cursor、Codex 等）的通用设计，为桌面端
> 最终交互模型定稿。

## 一、主流共识：可折叠的「进度追踪」（Progress Steps / Trace）

AI UX Playground 将其总结为：**将 Agent 的中间工作（思考、工具调用、搜索步骤）
作为可折叠的追踪记录展示，默认折叠保持界面安静，按需展开供验证/调试。**

| 平台 | 实现 |
|---|---|
| ChatGPT | 推理折叠在 **"Thought for Ns"（思考了 N 秒）** 切换按钮下 |
| Claude | 扩展思考（Extended Thinking）渲染为最终回复**上方**的可折叠块 |
| Perplexity | 可折叠 **"Steps"** 追踪，显示搜索查询与来源 |
| Cursor Agent | 工具调用与文件读取显示为可展开的时间线 |

**通用元素**（Tool Call Card）：工具名 + 可折叠参数 + 状态徽章（loading/success/error 颜色编码）+ 输出摘要 + 执行耗时 + 工具图标。

## 二、执行中的动态状态

主流用「一行动态状态 + 流式回答」组合，不是多个独立块：

- **活动状态栏**：图标 + 动画区分状态——🧠 思考中 / 🔍 搜索中 / 🔧 调用工具中 / ✍️ 撰写回复中 / ⚠️ 错误。
- **流式回答**：状态行下方持续逐字输出（推理内容流式渲染，避免"假死 N 秒"观感）。
- **状态文案要具体**（Claude Code issue #40453）："Planning approach for auth refactor..." 优于泛泛的 "Thinking..."；长思考每 ~10s 更新；给出进度（"Editing 2/5"）。

Kimi 网页版：状态文字区分「思考中」/「执行中」，颜色随状态变化；吉祥物小球空闲呼吸 → 工作时加载+计时 → 完成撒花。

## 三、完成后：追踪**保留**（默认折叠）而非消失

**反模式警示**（明确列出）：「追踪在响应结束后消失，无法事后审查」是反模式。
主流平台完成后**保留一个折叠的过程入口**（ChatGPT "Thought for Ns"、Claude 折叠 thinking、Perplexity Steps），默认收起，点击可回顾。

> 这与你之前 spec 的「完成后彻底消失」冲突——调研结论是主流**保留可折叠过程**，
> 便于复盘/调试/建立信任。

## 四、既有仓库调研（docs/desktop-agent-benchmark-research.md 2026-07-25）

- Codex 的**工具调用/活动摘要默认折叠**（社区要求默认展开，#23868）。
- thinking **折叠点击展开**；推理内容缓冲后一次性显示 → "假死 30 秒"观感（#8204）。
- 结论：**我们流式逐字渲染 + thinking 折叠的做法优于 Codex 的一次性缓冲，保持**。

## 五、与桌面端现状对照

| 项 | 主流 | 当前桌面端 |
|---|---|---|
| 执行中状态 | 一行动态状态 + 流式回答 | 两行简洁动画状态 + 流式回答（无图标/时长） |
| 思考展示 | 折叠 + 点击展开，可流式 | 状态行点击展开当前思考 |
| 工具展示 | 折叠卡片：名+参数+状态+耗时 | 状态行点击展开名+定长参数（无状态/耗时） |
| 完成后 | **保留可折叠过程追踪** | 彻底消失（与主流相悖） |

## 六、建议方向（供定稿）

1. **执行中**：一行（至多两条）简洁动态状态（思考中/调用工具，可加图标），流式回答下方持续输出。
2. **点击状态行**：展开当前项——思考内容（可流式）/ 工具名 + 参数 + 状态 + 耗时。
3. **完成后**：最终答案 + 产物 + 一个**默认折叠的「已用过程」**入口（点击可回顾完整思考/工具序列，含时长）——对齐主流，而非彻底消失。
4. 可选增强：状态文案具体化（如"正在分析文件…"）、耗时计时、工具状态徽章。
